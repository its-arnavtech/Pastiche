# 0006 cursor-opus: owned paths, dependencies, event envelope

- Context: the seeded task files list owned paths for T-014..T-016 (`src/remixer/events/`, `src/remixer/player/`, a FastAPI player) that differ from the `cursor-opus` brief (`src/remixer/analytics/`, `src/remixer/fatigue/`, `web/`, `tests/analytics/`, `tests/fatigue/`, `tests/web/`, later `tests/contracts/`). The brief also requires pure Python with no torch/CUDA, runnable on a plain CI machine, while the T-001 pyproject makes torch (CUDA index), demucs and openvino base dependencies.
- Decision:
  - The brief's paths win. Event schema, interpretation, heatmap and simulator live in `src/remixer/analytics/`; fatigue, credit, attribution and selection in `src/remixer/fatigue/`; the static player plus a stdlib mock backend in `web/`. The `owns_paths` of T-014..T-016 are updated to match.
  - `remixer.analytics` and `remixer.fatigue` import only the stdlib, numpy (attribution), duckdb and pyarrow (scale path), never `remixer.interfaces` or anything that pulls torch. `pyproject.toml` gets optional groups `analytics` (numpy, duckdb, pyarrow; also base deps today, listed so a CI job can install just these) and `web-test` (playwright), `hypothesis` in the `dev` group, and pytest settings `pythonpath = ["src"]` plus the `scale` (opt-in) and `web` markers. Plain-CI run without the torch stack: `uv run --no-project --with pytest --with hypothesis --with numpy --with duckdb --with pyarrow pytest tests/analytics tests/fatigue`.
  - The web UI reads the project name from the mock backend, which takes it from `remixer.PROJECT_NAME`, so the name stays in one constant.
  - One event envelope for every control: the T-014 fields plus an optional `payload` object. Playback types are the seven in spec section 5; rating (`rate_up`, `rate_down`, `rate_tired`, `rate_clear`) and insight-answer (`insight_yes`, `insight_no`, `insight_unsure`) types use the same envelope so the UI has one sink. Interpretation ignores non-playback types. `ParquetEventSink.append("playback_events", [e.to_dict() ...])` stores it as is.
  - `CHANGELOG.md` is not regenerated on this branch (generated file, regenerate on merge).
- Alternatives: separate event schemas per control family (two sinks, two validators); importing `remixer.interfaces` from analytics code (pulls numpy only today, but couples pure logic to the core module that also hosts torch-facing types).
- Consequences: the analytics and fatigue tests run on any CI machine; `uv run pytest` in the full project also runs them.

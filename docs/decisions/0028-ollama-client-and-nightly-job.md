# 0028 Ollama LLMClient and the nightly insight job

- Context: T-028 asks for an Ollama-backed `LLMClient` for the insight layer (decision 0020), T-029 for the job that runs `run_nightly` once per user per local night. Ollama is installed on this machine, but only `qwen3:4b` is pulled; the profile default was `llama3.2:3b`. A live smoke run against qwen3:4b returned empty `response` fields: qwen3 is a thinking model and, unless told otherwise, puts the whole answer in `thinking`.
- Decision:
  - `OllamaClient` maps `response_format="json"` to Ollama's `format: "json"` (it was being sent as an unknown option), sends `think: false` by default, falls back to the `thinking` text if `response` is still empty, and reports `available()` only when the server answers and the configured model is pulled. HTTP errors raise; the insight layer already turns them into fallbacks.
  - `profile.yaml` sets `llm.model: qwen3:4b`, the model already on the machine, rather than downloading another (about 2 GB).
  - `remixer.adapters.insight_job`: `run_job(adapters, now_ms)` loads `<data>/insights/state.json`, reads the `playback` event stream, runs `run_nightly` with the machine's UTC offset and a `CatalogTrackFeatures`, then atomically writes the state, `<data>/insights/nights/<day>.json` and `last_run.json`. A model that is down skips the night and leaves the state untouched. `CatalogTrackFeatures` derives 5-second windows for generated tracks from the recipe (section tempo, section index, stem roles playing) and, for source tracks, per-window loudness from the analysis row (`meta.window_lufs`, now written by `analysis_row`).
  - Scheduling: `remixer insights nightly` runs the night if `due()` (after 03:00 local and not yet run that local day), `--force` overrides. Registering it with Windows Task Scheduler is a persistent system change, so it is left to the user (docs/NEEDS_USER.md item 5).
- Live result: with the fix, qwen3:4b's narrator replies validate, but it garbles the `window_id` strings it is asked to echo in about half of analyst/skeptic replies (e.g. `dislike-0:60000-70000`). The pipeline rejects those and falls back to its deterministic rules, which kept precision at 1.0 on the 6-night confound fixture. A larger model, or echoing a short index instead of the full id (insight layer, cursor-2), would raise the share of model-written hypotheses.
- Alternatives: pulling llama3.2:3b (a download the user did not ask for); a built-in scheduler loop (another long-running process to babysit).
- Consequences: tests/contracts/test_insight_job.py covers the client against a scripted Ollama HTTP server (role round-trip equals MockLLM, malformed replies fall back, model down skips) and the job (night equals a direct run, rerun makes no calls, state survives a down model, recipe window features).

# 0029 Real FastAPI player backend over the adapters; browser tests run against both backends

- Context: decision 0016 shipped the player against a stdlib mock (`web/mock_server.py`) and asked for a real FastAPI backend with the same six routes. The player's Playwright tests (cursor-opus) were skipping on this machine: Playwright 1.64 wants Chromium build 1248, and only 1194 is cached, so it needs a browser download that agents do not make on their own.
- Decision:
  - `remixer.server.app`: `PlayerBackend(adapters)` + `create_app()` (FastAPI, CORS for cross-origin event posts, `no-store`), started with `remixer serve [--demo]`. Tracks come from the catalog (`tracks` rows with audio, plus the newest render of each recipe lineage as a generated track: `track_id` = root id, `track_version` = recipe id). Audio comes from the blob store with byte ranges. Events are validated against the T-014 schema and appended to the `playback` Parquet stream, which the nightly insight job reads; each row also stores the posted JSON and an arrival counter, so `GET /api/events` returns them exactly as posted and in order. The inbox is the nightly job's `InsightState` with answers from the stream applied, never evaluated before the night that produced it. Static files come from `web/`, refusing `.py` and path escapes.
  - Dependencies go in a new `player` extra (fastapi, uvicorn, httpx); the module imports FastAPI lazily so the CLI works without it.
  - `seed_demo()` loads the mock's synthetic demo tracks and its seeded insight history into a real data directory.
  - `tests/web/conftest.py` gains a `backend_kind` parameter: every browser test runs against the mock and the real backend. Its browser fixture falls back to the system Microsoft Edge (`channel="msedge"`) when the bundled Chromium build is missing, and ignores the console 404 for `/favicon.ico` that full Edge requests by itself.
  - `tests/test_player_backend.py` covers the routes without a browser.
- Alternatives: Starlette's `FileResponse` ranges (the mock's exact 206/416 behaviour is simpler to keep by hand); downloading Chromium 1248 (left to the user, NEEDS_USER item 3).
- Consequences: all 21 browser tests pass against both backends (42 runs) on Edge 156; the full suite is 411 passed, 0 skipped. Parquet writes one part file per POST, fine for one local listener; compaction is a later concern.
